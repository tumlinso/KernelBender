# Problem-first opportunity index

Keep the ten bridges as the first design vocabulary. Use this index when a problem needs a concrete capability or construction beyond those short bridges. A useful invocation usually opens this page, one affordance card and one construction card. Follow an exact KernelWiki contract only when its target, numeric form, access scope or participant rules could change the design.

|---|---|---|---|

| Small categorical rules, fixed local graph patches, lookup, compaction, or equal-key grouping | [Bit and routing circuits](affordances/bit-routing.md) | [Positional routing](compositions/positional-routing.md) and [discrete state](compositions/discrete-state.md) | Compare direct packed/CSR/library work; include encode/decode and external-ID recovery. |

## Build a new combination

Use the source idea as a reusable mapping, not as a stored answer. Name the caller-visible equation; choose where the semantic values live; compose a few mechanisms that preserve that equation; then compare the whole region. For example, a local categorical graph update might combine a stable bit-plane encoding, a lane/bit neighborhood map, a threshold mask as the next stage's input, and rank/select only at the external output boundary. Its useful lifetime can be written as `encode + t * (Boolean transition + required exchange) + output extraction`. Compare packed sparse/dense graph kernels at the same degree distribution and output contract. Test tail vertices, cross-word edges, empty frontiers and any dynamic-topology invalidation. Neither a mask encoding nor the composition itself predicts speed.

When joining two cards, write the intermediate representation explicitly. Check each boundary for participant scope, precision, update lifetime, conversion, synchronization, code size and shared resources. A pairing is rejected if its outputs cannot feed the next owner without more work than the removed boundary, or if it depends on a hardware fact that KernelWiki does not establish.

## Exact target and evidence route

Use [architecture grounding](architecture.md) and the [KernelWiki contract map](wiki-contracts.md). The exact `sm70` MMA coordinate and `sm80` async-copy pages are different target contracts. Do not infer Volta `cp.async`, Hopper TMA/warp-group behavior or restricted command-engine access from an analogous concept. Evidence cards identify bounded results; they are not general rankings.
