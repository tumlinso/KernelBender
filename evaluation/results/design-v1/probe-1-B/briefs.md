# E01 — Compute only the observed energy

**Disposition: probe.** The consumer is one scalar per row, `||XAB||²`, under a tolerance against a direct FP32 chain. `B,K,M,P` sizes, GPU and batch layout are missing, so no global cost crossover or numerical bound can be claimed.

**Recommendation and baseline.** Keep FP32 cuBLAS GEMMs for `U=XA` and `Y=UB`, then reduce `Y²` per row; fuse the last square/reduction into an owned second-stage tile when the missing dimensions and library boundary make that practical. This preserves the direct operator more closely than reassociation and avoids treating either matrix as caller-visible. The temporary `U` costs `4*B*M` bytes written and read per batch; the optional `Y` costs `4*B*P` bytes before reduction. Cost is about `2BKM + 2BMP` FLOPs per batch, plus launches and those transfers.

**Materially different candidate.** At the epoch update, form `C=AB`, retain `4*K*P` bytes, and compute `XC` then row energy for each query. Cost is `2*K*M*P + 2*Q*B*K*P` FLOPs for `Q` batches, versus `Q(2BKM+2BMP)`, plus preparation and retained storage. It removes the per-query M reduction but changes FP32 grouping and rounding. It is plausible at Q=32 only when `M` is useful work to eliminate and the numeric test passes. Updating either parameter invalidates C. Q=1 has little amortization.

If `XA` must be rounded to FP32 before B, `AB` reassociation violates the contract; retain the direct chain. If A or B changes per batch, recompute C each batch and include that cost; favor the direct chain absent another reuse. First compare both paths against the exact direct FP32 oracle on cancellation-heavy and boundary-scale inputs, then measure complete Q=1 and Q=32 epochs with preparation and updates charged. Reject any tolerance failure or total-cost loss. # E02 — Preserve every position through local transitions

**Disposition: probe.** Each step reads the old two-bit state at i and i-1 plus the fixed mask at i, then writes every final position and the exact count of state 3. Keep a synchronous old/new-state boundary at every step.

**Conventional route.** Tile contiguous sites into CTAs. Load a core plus T left-halo sites, retain byte states and masks in shared memory, perform T rule applications with the valid interval shrinking from the left by one site per step and a barrier between old and new buffers, and emit only the core bytes. The rule is a 32-entry truth table shared by all sites. A one-CTA periodic tile handles N=31 or 33, including T=32; larger N uses independent cores and halo recomputation, with wrapped input at site zero. Produce one partial count per tile and reduce it, or use a correctly initialized integer atomic. This avoids T grid-wide launches and does not require a packed global scratch array.

**Different candidate.** Within each tile transpose states and mask to bitplanes, compile each output bit from the actual table, shift the old-state planes to supply i-1, and keep planes through all T steps. Decode final bytes once and POPC `(state_bit0 & state_bit1)` for state 3. Mask invalid tail bits for N=31, 33, and 65537; the final word has 31, 1, and 1 valid bits respectively for N=31, 33, 65537. Explicitly bridge the highest valid site to site zero; a normal 32-bit shift alone is wrong. For N=1024 there are 32 words; for N=65537 there are 2049. Tile halos preserve the left-only dependency without inter-CTA synchronization; update only the interval whose left dependency remains inside the loaded halo. Packing, partial-word logic, extraction, and tile occupancy may erase the Boolean work saved, especially for N=31/33 and T=1.

If each intermediate is observable, decode and materialize each step or retain a packed API contract; per-step byte output weakens the bitplane case. If masks change each step, load or repack that step mask and charge its traffic; if a new mask arrives only at a global step boundary, a launch or synchronization boundary may be unavoidable. First exhaust all 32 rule entries, every tail residue and periodic wrap on a CPU oracle, then test exact GPU outputs and full epoch cost over all N,T pairs. Reject bitplanes if conversion and halo costs lose to tiled bytes. References: `/sources/atlas/mechanisms/M06.md`, `/sources/atlas/mechanisms/M14.md`, `/sources/atlas/compositions/C06.md`, `/kernelbender/references/bridges/bitplanes.md`, `/kernelbender/references/bridges/parallelism.md`.

# E03 — Reuse one decoded FP32 weight matrix

**Disposition: probe.** The represented matrix has `64*128=8192` weights: 4096 packed bytes, 256 FP32 scales (1024 bytes, four per K row), and a 32 KiB FP32 decode. The decode contract is exactly binary32 `float(q)*scale`; do not round to FP16 or move scale through accumulation.

**Conventional route.** Decode q and scale once into row-major FP32 W, then use FP32 cuBLAS SGEMM for `Y=XW` and `Z=VWᵀ`. The same immutable W serves both concurrently; for Z, each output k reduces contiguous `W[k,m]`. Charge one decode launch, 32 KiB write, and each consumer read of W. Each of Q query pairs then costs two `8x64x128` products and writes 4 KiB Y plus 2 KiB Z. This is a straightforward library baseline with a stable shared owner.

**Alternative.** Fused consumer kernels decode signed nibbles beside each FP32 multiply/FMA, reuse each decoded weight across the eight query rows, and avoid dense storage and the preparation launch. Both consumers read the same packed input safely, but each repeats decode per pair; compare for Q=1 and Q=64 rather than assuming the larger case wins. If dense W is prepared, publish it only after completion; key it to the q/scale epoch. Wait for both readers before replacing source data or rebuilding W. A weight update invalidates all prepared values.

First compare both outputs to direct FP32 accumulation with all nibble values, scale boundaries, negative inputs and cancellation cases; then time cold Q=1 and Q=64 epochs including decode, both consumers, outputs and update. Reject any rounding mismatch. The SM70 W4A16 source rounds decoded weights to FP16 and tests different dimensions, so its speed result does not transfer to this FP32 contract. No target is specified; architecture-specific low-bit or tensor instructions remain unselected.
